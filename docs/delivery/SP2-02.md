## Local demonstration

Restart your dev process after setup/config changes:

```sh
npm run local:env
npm run dev
```

Open http://127.0.0.1:3000/login with your generated individual credentials, then use “Identifier un produit” in workspace. In OFF_MODE=fixture: 0012345678905 gives found, 0000000000123 incomplete, 12345678 absent and 9999999999999 simulated unavailable. Typed input always works without camera permission. No-code/manual label input previews an unrecorded reference and is cleared when the workspace locks.

For explicit controlled real reads, set OFF_MODE=live in your private .env, retain the required OFF_USER_AGENT and restart dev. Default OFF_TIMEOUT_MS=5000/OFF_CACHE_SECONDS=900. Do not send restaurant/private fields or use a public write API. API v3.4 is intentionally pinned; current OFF v3.6 has different nutrition/tag schemas. See the [contract/reuse notes](../architecture/contracts/product-identification.md) before broader reuse. EVIDENCE/AI/OCR/OFFLINE remain disabled. Automated smoke requires fixture mode and refuses live provider dependency.

### Product card update

The lookup now requests the public front thumbnail and displays it with Open Food Facts contributor attribution and CC BY-SA 3.0 link. Only HTTPS images.openfoodfacts.org product-image paths are accepted; no credentials or referrer are sent. Images load directly from the public host, are not persisted, and missing/failed photos show a placeholder. Declared allergen tags are highlighted with French labels; missing declarations remain unknown. The previous browser no-external-request evidence applies to fixture mode (which has no photo), not live thumbnail loads.
